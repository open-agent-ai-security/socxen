Summary
The Agent (as modeled)

socxen is a SOC analyst skill suite for an Exabeam New-Scale tenant, worked by a human at a Claude Code or Codex terminal. Three prompt-shaped skills — one alert or case at depth, a read-only queue sweep, and a propose-only detection-tuning pass — drive a bundled local MCP bridge that proxies every call to the tenant over an OAuth bearer minted from a plaintext key file in the operator's home directory. Its untrusted inputs are the tenant's own telemetry, the remote MCP's tool definitions, and whatever an analyst pastes into the session; its consequential capabilities are a small, gated write surface — dismiss an alert, close a case, write a case note, open a case, send platform mail. There is no shell, no code execution and no containment reach anywhere in the runtime path. The trust surfaces that matter are the human gate in front of dismiss and close, which ships active as a bundled hook rather than as an operator opt-in, and the two deterministic guardrails inside the bridge that screen what is read and neutralize what is written.

Priority Threats (led by attack paths)

The controls here are real and in code, so the things to deal with first are the edges where a real control stops short of the whole surface it is described as covering. The sharpest is the paste. An analyst pasting an alert, a queue export or a case payload is a documented way to start work, and that text never crosses the bridge, so the deterministic screen never touches it — the only defense is the skill's instruction to distrust it. From there an attacker-authored payload can steer a verdict and be written back into the tenant as a case note with no human prompt, because the two additive writes are prompt-free for every skill and the write-side neutralizer only rewrites eight named fields. Fix order: get the screen onto the paste path, scope the sweep's writes, and invert the neutralizer's field policy to match the deny-by-default policy used beside it for tools.

Two more are worth scheduling. Reading a case has no size ceiling — only the three search tools are bounded — so an oversized case read ends with the harness dumping raw tenant content into a file on the analyst's laptop, which is exactly the copy the policy forbids; and when a tenant tool call fails, a few hundred characters of the tenant's own text are written into the local audit file that the documentation promises never holds tool results. Beyond those, note two quieter gaps: the vendor's tool definitions tell the model to ignore the analyst and the model was measured obeying them every single time, with no stored baseline to catch a definition that changes between sessions; and the supported-model floor is stated only in the install docs, so nothing stops the suite running on a model its adversarial testing never covered. The gate itself, the containment deny-list, the close-by-another-route guards and the dependency pinning all hold up — they are what keeps this picture as narrow as it is.

  5. Bundled PreToolUse gate [PRAX-2026-09-15-002] exabeam_create_case_notes and exabeam_create_case are allow-tier for every skill, so the write is dispatched with no human prompt.
  6. Bundled Exabeam MCP bridge The bridge forwards the write on its single call path, treating anything not a known read as a write.
  7. Output neutralizer [PRAX-2026-09-15-003] Neutralization rewrites only values whose key is one of eight named free-text fields, so coverage is fixed at release time rather than deny-by-default.
  8. Remote Exabeam New-Scale MCP / API [PRAX-2026-09-15-003] Consequence: attacker-authored content persists in a tenant case record that other analysts read and that exports carry onward.

  3. Input code-point screen The screen removes smuggling code points but cannot remove language, so directive text and inflated content pass through.
  4. triage-cases queue sweep [PRAX-2026-09-15-009] The sweep converges on a case and calls exabeam_get_case_details, which takes only a caseId and cannot be narrowed at the API.
  5. Host session model [PRAX-2026-09-15-007] The hijack: the model follows the definitions' own field guidance over the skill's cookbook — measured compliance on 1,840 of 1,840 searches.
  6. Bundled PreToolUse gate The read is allow-tier, so it is dispatched without a prompt or a size question.
  7. Bundled Exabeam MCP bridge [PRAX-2026-09-15-009] No byte ceiling exists outside the three search tools, so the full payload is returned unbounded.
  8. Claude Code host session [PRAX-2026-09-15-009] The host spills the oversized result to a local working file and hands the agent the path.
  9. Harness working file for oversized reads [PRAX-2026-09-15-009] Consequence: raw tenant case content comes to rest outside the tenant on the workstation, which the remit forbids and the skill then reads back.
Text an attacker plants in telemetry is copied into the local audit trail
  1. Remote Exabeam New-Scale MCP / API Untrusted origin: alert, event and case fields are attacker-influenceable, and a failing tool returns the tenant's own text as the error.
  2. Bundled Exabeam MCP bridge The bridge raises the upstream result's text as the exception on the isError path.
  3. Input code-point screen The text is screened for code points and capped, but its content is preserved.
  4. soc-investigate loop (and rule-tuning) The loop retries or pivots on the failure, keeping the attacker's chosen field in play.
  5. Host session model The hijack: the model reissues reads against the fields the planted content steers it toward, producing more error paths.
  6. Bundled PreToolUse gate Reads are allow-tier, so each attempt is dispatched without a prompt.
  7. Bundled Exabeam MCP bridge [PRAX-2026-09-15-005] Each failure calls telemetry.tool_error with up to 300 characters of that upstream text.
  8. ~/.socxen/telemetry.jsonl audit trail [PRAX-2026-09-15-005] Consequence: attacker-authored content is persisted in a durable local audit file the logging docs promise never holds tool results — a second copy of the evidence outside the tenant.
