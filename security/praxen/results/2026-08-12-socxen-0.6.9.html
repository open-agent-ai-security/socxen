Executive Summary
Agent Remit (as declared)
socxen is an agentic SOC analyst that works a single Exabeam New-Scale alert or case end to end for a human analyst at an interactive terminal — gathering evidence across the platform's read surface, correlating a timeline, mapping to MITRE ATT&CK, and reaching a threat or false-positive verdict. It may read freely and write additively (open a case, update its working state, write case notes), but dismissing an alert or closing a case must be blocked by a harness-enforced permission rule and confirmed in-session, so suppression never rests on the model's own compliance. Containment is recommended to the analyst and never executed, telemetry retrieved from the tenant is evidence rather than instruction, and the platform credentials, the free-text evidence, and any neutralized hostile payload must never reach the audit log or leave the operator's host.
Behavior Summary (as observed)
The dominant pattern is a sharp split between the two enforcement layers. Everything the project implements in code is genuinely operative and unconditional — neutralize_output() fails closed on every write, canonicalize() runs on every read result, the audit trail is on by default with a privacy allowlist, and no configuration switch turns any of them off — while the governance layer that guards the one action the project itself names as its worst-case harm is a JSON snippet the operator must copy by hand. install.sh verifies that snippet and prints a warning when it is absent, but never merges it, so on the shipped default path both the dismiss/close ask gate and the invariant-tested 68-rule containment deny tier are inert and the model's own in-prompt question is the only lock. A second, quieter theme runs alongside it: the bridge sees a great deal the analyst never does — stripped smuggling code points, a telemetry destination change, a screening failure — and reports all of it to stderr, which never surfaces in the session.
Scope of Analysis
A Claude Code plugin: a prompt-only skill (skills/soc-investigate/SKILL.md plus a reference/ corpus), a permissions pack shipped as settings.snippet.json, and a bundled stdio MCP bridge (connector/exabeam-mcp-bridge.py) auto-registered through .mcp.json that mints and refreshes an OAuth client-credentials token from ~/.exabeam-mcp.env and proxies every call to the remote Exabeam MCP. The bridge is the single chokepoint and carries three always-on code-layer controls: canonicalize() strips unambiguous Unicode smuggling from read results, neutralize_output() defangs formulas and links in the six free-text write fields and fails closed, and observra_logging writes a default-on, privacy-allowlisted, rotating JSON-lines audit trail to ~/.socxen/telemetry.jsonl. Supporting practice is unusually complete for a pre-1.0 project — an invariant-tested governance surface, a CycloneDX AI BOM drift-gated in CI, an eval harness, and a red-team programme with dated results. The material divergence from the remit is that install.sh never applies the permissions pack: it checks for it and warns, leaving the gate the remit calls harness-enforced as an unmerged document.

What's Working Well

Controls and behaviors that are correctly implemented and verified during this scan. These represent areas where the agent's implementation aligns with its stated policy and security best practices.

Output neutralization is deterministic, fail-closed, and on the real write path

Every case-note and alert/case write has its six free-text fields defanged by neutralize_output() before it leaves the bridge, and a neutralizer error propagates rather than being swallowed, so a raw payload is never persisted. Input canonicalization runs on every read result with no off switch

Read results are stripped of unambiguous Unicode smuggling code points before the model reasons over them, with linguistically legitimate joiners deliberately preserved, and the hygiene record is kept out of band so it cannot be forged back into the content.

Governance drift is enforced by an automated invariant test, not reviewer memory

A CI-gated test derives the expected containment deny set from containment-tools.md and fails on any missing or extra rule, and a second test derives the plugin tool prefix from plugin.json plus .mcp.json so the bug that once made the gate inert cannot recur silently.

The audit trail is privacy-preserving by construction
