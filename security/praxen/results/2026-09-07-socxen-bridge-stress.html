Executive Summary
Agent Remit (as declared) · Remit v1.5
socxen is declared as an agentic SOC skill suite that works one Exabeam New-Scale tenant at three depths — `soc-investigate` takes a single alert or case end to end to a threat or false-positive verdict, `triage-cases` sweeps the open queue read-only, and `rule-tuning` diagnoses noisy detections and proposes tuning it may never apply. Its authorized capability set is the Exabeam read surface plus four non-destructive write tools (create case, update case, case notes, update alert) and a human-confirmed platform email tool; its counterparties are the analyst at the terminal, the operator's own tenant, and nothing else. Containment is the defining prohibition: socxen must recommend endpoint isolation, account disable or blocking to the human and never execute, initiate or claim one. Dismissing an alert or closing a case must be blocked by a host-enforced gate that is active on a fresh install with no operator opt-in, and every persisted write must pass a deterministic neutralizer that masks credentials and de-fangs active content without depending on model behavior.
Behavior Summary (as observed)

The dominant pattern is a genuinely enforced agent whose remaining gaps are all enumeration where the code has already learned to prefer defaults. socxen's own recent work made tool classification fail toward "treat it as a write" and made unclassified tools ask rather than inherit the session default — but the containment and rule-write deny tier is still a list of names, the write-side neutralizer still picks fields from a fixed set, and the read-side canonicalizer covers tool results while list_tools() hands the model the remote server's tool descriptions verbatim, on a channel whose own vendor text already issues instructions to the caller.

The second theme is attestation outrunning verification: plugin/install.sh tells the operator the bundled hook has dismiss and close covered without ever calling the installed_hook_state() check that ships beside it in preflight.sh, and nothing reconciles a report that claims a disposition change against the bridge's record of what was actually called — the failure the project's own below-floor control run reproduced five times out of five.

Scope of Analysis
A Claude Code and Codex plugin: three skill prompts under `plugin/skills/`, a bundled stdio MCP bridge (`connector/exabeam-mcp-bridge.py`, PEP 723 with a hash-pinned `.lock`) that proxies every call to the remote Exabeam New-Scale MCP and mints its own OAuth token, and a `PreToolUse` hook (`hooks/gate.py`) the plugin manifest wires up so the gate is live the moment the plugin is enabled. The bridge is where the deterministic controls sit: `canonicalize()` strips invisible smuggling code points from every tool result, `neutralize_output()` masks secrets and de-fangs links and formulas in every write argument (fail-closed), and `observra_logging` writes a default-on, bounded, metadata-only audit trail to `~/.socxen/telemetry.jsonl` beside the hook's own `~/.socxen/gate.jsonl`. One generated tier source, `skills/soc-investigate/permissions.json`, feeds the hook, the optional `settings.snippet.json` permission pack and the Codex approval map, with CI drift checks holding the three in sync. Structurally this matches the remit closely; the divergences are at the edges — the installer's account of the gate, what the screening and neutralization passes are scoped to, and what the audit trail says when it is switched off — read from a pinned clone at `16dea29`.

What's Working Well

Controls and behaviors that are correctly implemented and verified during this scan. These represent areas where the agent's implementation aligns with its stated policy and security best practices.

Human-in-the-loop gate ships active and fails closed at every branch

The plugin manifest wires a `PreToolUse` hook, so the gate is live the moment the plugin is enabled rather than waiting on an operator merge, and every path through it lands on "ask" — an unclassified tool, an unreadable tier file, a malformed event, a thrown exception — with `|| exit 2` covering a missing interpreter.

plugin/hooks/gate.py:113-125 and plugin/hooks/hooks.json:5-13

Deterministic write-side neutralizer that measurement shows is load-bearing

Every write argument in the free-text set is masked and de-fanged before it leaves the bridge, fail-closed, with link de-fanging deliberately ordered before redaction so a redaction match can never re-arm a live link and typed placeholders surviving repeat passes intact.

plugin/connector/neutralize_output.py:857-905

One generated permission-tier source with CI drift gates across three enforcement points

The hook, the optional settings pack and the Codex approval map are all derived from `permissions.json`, and `gen_identity.py --check` plus `gen_codex_mcp.py --check` fail the build if any of them drifts, so the three enforcement layers cannot silently disagree.

plugin/skills/soc-investigate/permissions.json:1-3 with .github/workflows/ci.yml:56-63

The bridge classifies an unknown tool as a write, and an unreadable tier file as no reads at all

Read tools are derived from the shipped tier file and everything else is neutralized, audited and refused in a dry run, so a tool the release never saw fails toward the safe direction instead of sailing past a name enumeration.

plugin/connector/exabeam-mcp-bridge.py:375-403

Adversarial programme whose findings changed the architecture, with a finding-to-fix ledger

A 22-fixture corpus in four classes is run against socxen's own defences before each release across four models, and the fixed-findings table traces each landing to an issue, the pull request that fixed it and the re-verification run that closed it.

security/redteam/HISTORY.md:118

Hash-pinned dependency tree with a required vulnerability audit and drift-gated bills of material

The bridge's resolved tree is locked with 413 artifact hashes, `pip-audit --strict` runs as a required step on every push and pull request, and the CycloneDX SBOM and AIBOM are regenerated and compared against the committed copies in CI.

plugin/connector/exabeam-mcp-bridge.py.lock with .github/workflows/ci.yml:92-101

Two default-on audit trails with privacy enforced by allowlist rather than by redaction

Both the bridge's telemetry and the hook's decision log record only identifier and enumeration fields drawn from a fixed allowlist, capped and bounded, so the note, description and reason text a planted payload rides in can never enter either file.
