Summary
The Agent (as modeled)

socxen is a SOC analyst suite that runs inside a security analyst's coding agent: three skill prompts drive an investigation of an Exabeam alert or case, a queue sweep, or a detection-tuning proposal, all reached through a bundled local connector that proxies every call to the customer's Exabeam platform. Its untrusted input is the tenant's own telemetry — alert, event and case text written by whoever generated the logged activity — plus, less obviously, the remote connector's own tool descriptions. Its consequential capabilities are narrow and well chosen: containment is denied outright, detection-rule writes are denied, and dismissing an alert or closing a case is held behind a gate that ships switched on and asks a human every time. The surfaces that matter most are therefore not the dangerous tools but the two places untrusted text reaches the model, and the small set of platform writes that were deliberately left prompt-free so that escalating is never friction.

Priority Threats (led by attack paths)

Deal first with the connector's own tool descriptions. They carry text addressed to the model, the connector screens them and reports that they do so but forwards them unchanged, and the project's own measurement is that the model follows that text over its skill instructions essentially every time. Because those descriptions are neither signed nor version-pinned and nothing keeps a baseline to compare against, a changed or hostile description would only be noticed after the fact — and the writes it could steer, opening a case and writing case notes, run without asking anyone. The same shape reaches the agent through ordinary telemetry: the read-side screen removes invisible smuggling characters but nothing filters a plainly worded false explanation, so planted narrative can end up persisted in the case record and read back as fact by the next investigation. Treat those descriptions as untrusted vendor text rather than instructions, keep and compare a baseline of them, and mark agent-authored notes so a later session can tell them apart from analyst evidence.

Two smaller items deserve attention next. The installation guide advertises a third way to run the suite — any capable coding agent following the skill folder — on which neither host enforcement layer exists, while the skill itself tells the model that its own in-session question is the lock that always holds; that combination is the one place a suppressed alert could happen with no human in the loop, and the guide should say so plainly or drop the path. Beyond that: an upstream tool failure writes the platform's own error text into an audit trail that is otherwise deliberately metadata-only, the connector accepts an unencrypted endpoint without complaint so a mistyped configuration would send the API key over the wire in the clear, the prompt-free read tier includes tools the platform has not even exposed yet, and oversized results are spilled by the host to an unredacted local file that outlives the session. None of these needs an attacker to be clever; all four are small, contained fixes.
