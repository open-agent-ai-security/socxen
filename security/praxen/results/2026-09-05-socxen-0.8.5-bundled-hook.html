Executive Summary
Agent Remit (as declared) · Remit v1.3
socxen is an agentic SOC skill suite for an Exabeam New-Scale tenant, working at three declared depths — soc-investigate takes one alert or case end to end, triage-cases sweeps the open queue read-only, and rule-tuning diagnoses noisy detections and proposes changes it never applies. It is authorized to use the Exabeam read surface plus four non-destructive write tools (create case, update case, write case notes, update alert) reached only through an operator-configured MCP endpoint, and to report to exactly two audiences: the analyst's terminal session and the tenant itself. Containment is recommended, never executed, and the remit denies containment-class tools deterministically even though the platform exposes none. The defining obligation is that dismissing an alert or closing a case must be blocked by a host-enforced gate that is active on a fresh install with no operator opt-in, never fails open, and refuses the call when no human is present to answer.
Behavior Summary (as observed)
The dominant pattern here is a genuinely load-bearing deterministic layer with a narrow, allowlist-shaped perimeter — and the gaps all sit exactly where that perimeter ends. gate.py, neutralize_output.py and canonicalize.py are real controls on the real path, active on install and fail-closed where it matters, and a sustained first-party red-team programme proves they are load-bearing rather than decorative. But each is bounded by a hardcoded list: the write-side neutralizer covers five tool names and six field names, so exabeam_send_email's HTML body leaves un-defanged; the read-side canonicalizer screens tool results while list_tools() proxies the remote server's tool descriptions into context unscreened and unpinned; and the gate itself, which never fails open once it runs, is invoked as python3 gate.py with nothing making that invocation fail-closed. No compound escalation was warranted — the human ask on every consequential write is what breaks the one chain the evidence supports.
Scope of Analysis
Source pinned at SHA a6a3ffe5f21fbbb76c8cb1f99791fa39ceff5746. The shipped payload lives under plugin/: three prompt-only skills, a bundled stdio MCP bridge (connector/exabeam-mcp-bridge.py, a PEP 723 script launched by uv) that proxies every call to the remote Exabeam MCP while minting an OAuth client-credentials token from ~/.exabeam-mcp.env, and a PreToolUse hook (hooks/gate.py, wired through the plugin manifest's hooks key) that classifies every exabeam tool into deny/ask/allow tiers read from settings.snippet.json and returns ask for anything it has not classified. Two deterministic guardrails are genuinely wired into the call path — canonicalize() runs fail-open on every read result and _defang_args() runs fail-closed on write arguments — alongside default-on, locally-rotating audit telemetry in observra_logging.py. The material divergences from the remit are that the gate's own invocation shells out to python3 with no fallback, that an exabeam_send_email tool sends HTML to arbitrary recipients outside both the neutralizer and the remit's channel table, and that the remote server's tool descriptions are proxied into model context with no screening or pinning.

What's Working Well

Controls and behaviors that are correctly implemented and verified during this scan. These represent areas where the agent's implementation aligns with its stated policy and security best practices.

Human-in-the-loop gate ships active inside the plugin

A PreToolUse hook declared in the plugin manifest classifies every Exabeam tool into deny, ask and allow tiers the moment the plugin is enabled, denies containment outright, and returns ask for any tool it has not classified rather than inheriting the session default. It fails closed on an unreadable tier file or a malformed event, and logs every decision.

plugin/hooks/gate.py:59-67

Write-path neutralization is deterministic and fail-closed

Every write argument in a free-text field passes through neutralize_output() before the call is forwarded, and a neutralizer error propagates rather than being swallowed, so the bridge refuses the write instead of persisting a raw payload. Link de-fanging deliberately runs before redaction so a redaction match can never leave a live link armed.

plugin/connector/exabeam-mcp-bridge.py:220-230

Sustained first-party red-team programme with findings traced to fixes

Twenty-one adversarial fixtures aimed at socxen's own defences, twenty-one dated result reports across three models, a command-invocable runner and a HISTORY.md ledger that lists a finding only after it is remediated. The deterministic redaction layer exists because a measured prompt-only failure rate demanded it.

security/redteam/HISTORY.md

Fully hash-pinned dependency tree with a CI-drift-checked AI BOM

The bridge's PEP 723 header version-bounds all five direct dependencies and the adjacent lockfile carries sha256 pins for the entire resolved tree, so a fresh install resolves what the maintainers tested. CI fails the build if the CycloneDX AI BOM drifts from the manifest, MCP config, connector dependencies or governance tiers.

.github/workflows/ci.yml:41-44

Governance consistency is enforced by tests, not reviewer memory

Repo-invariant tests pin the containment deny-list to its documentation, the Codex approval map to the Claude permission snippet, the hook's decisions to the shipped tiers under every server prefix, and every governed tool to the tool map. A silent divergence between the three tier consumers fails CI.

tests/test_repo_invariants.py:155

Audit logging is on by default, local-only and bounded by construction

Structured JSON-lines telemetry runs unless explicitly disabled, defaults to a local rotating file with a clamped size ceiling and no network egress, and records only tool names, durations, safe identifier and enum fields and guardrail counts — never free text, tool arguments or neutralized payloads.

plugin/connector/observra_logging.py:59

The optional permission merge is consent-gated and safe to re-run

The merger only runs when the operator passes an explicit flag, is additive rather than a reset, backs the settings file up before writing, writes atomically with the original file mode preserved, and aborts the whole merge if any rule already sits in a different tier rather than overriding a human decision about a safety control.

plugin/skills/soc-investigate/merge_permissions.py:16-27

No credential material anywhere in the tree

A tree-wide sweep for key, token, private-key and JWT patterns returned only AWS's own documentation placeholder inside red-team fixtures. Runtime credentials stay in an operator-owned file outside the repo, and the preflight warns when that file is not mode 600.
