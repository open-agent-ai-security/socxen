BEHAVIOR SUMMARY
------------------------------------------------------------------------------
The dominant pattern here is not a missing control — it is a boundary drawn by
enumeration rather than by closure. socxen's enforcement is real, code-level,
and active on install: the bundled gate.py hook fails closed on every
uncertainty path, neutralize_output() is fail-closed and measurably
load-bearing, and one tier source drives all three host configurations under
CI drift checks. But nearly every gap found is the same shape — a control
whose reach is fixed by a list of today's names. The deny tier enumerates
containment verbs and analytics-rule writes; WRITE_TOOLS and _DEFANG_FIELDS
enumerate today's five write tools and their fields; the hook decides whose
call it is governing from a substring of the MCP server's name. The one
control gap that is not merely a boundary question is the bridge's
list_tools() passthrough: tool metadata from the remote MCP reaches the model
without canonicalization or screening, and that channel is already carrying
instruction-shaped text the project has had to counter in a skill prompt.
Alongside it, no code control distinguishes an additive case update from an
overwrite of an analyst's existing free-text record.
