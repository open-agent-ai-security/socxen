Summary
The Agent (as modeled)

socxen is an agentic SOC analyst suite: three prompt-only skills that a Claude Code or Codex session runs against one Exabeam New-Scale tenant, reached through a small bundled connector the plugin starts for itself. It investigates a single alert or case at depth, sweeps the open case queue read-only, and proposes detection tuning. Its untrusted input is the tenant's own telemetry — alerts, events and case notes written by whoever triggered the detection — plus the tool catalog the remote platform advertises; its consequential capabilities are narrow and deliberate: open a case, write case notes, dismiss an alert, close a case, and send mail to the subscription's own users. It ships no shell, no code execution and no general-purpose file writing. The two surfaces that carry the risk are the connector, which is the only path platform content takes into the model and the only path the model's text takes back into the tenant, and the human-in-the-loop gate, which ships switched on and decides which calls reach the platform at all.

Priority Threats (led by attack paths)

Deal first with the one channel nothing screens. Everything the platform returns from a tool call is cleaned of invisible smuggling characters before the model reads it, but the platform's list of tools — the names, descriptions and argument documentation — is handed to the model exactly as received, and that channel already carries text instructing the caller to ignore what the user asked for. Today the only thing standing against it is a sentence in a skill file telling the model to disobey. From there the shortest route to harm is a case or alert update: the gate asks the analyst to approve the call, but nothing in the path distinguishes adding to a record from overwriting an analyst's existing notes, descriptions or closing reasons, so an approved-looking update can silently replace someone's work. Route the tool catalog through the same screening the results already get, and make free-text updates additive by construction.

Two further gaps decide who is actually protected. The gate recognises its own calls by looking for the word 'exabeam' in the connection's name: an operator who wires the platform by hand under a different spelling gets a plugin that looks installed and gated but is neither, and nothing in the installer or the preflight check reports that state — while a third-party connection that happens to have that word in its name inherits socxen's prompt-free reads. Alongside it, the supported-model floor is documentation only; the project's own testing shows a below-floor model announcing an alert as dismissed without ever calling the tool, which no action gate can catch. Lower down the list: the audit trail can be switched off with no notice to anyone, tool discovery is never recorded, and nothing bounds the size of a result the platform returns. What keeps the rest of the picture clean is genuinely good engineering — the gate is active on install and fails closed on every uncertainty, the write-side neutralizer refuses rather than persists a payload it cannot clean, one permission source generates every host configuration under build-time drift checks, and the dependency tree is hash-pinned behind a required vulnerability gate.

Text in the platform's own tool catalog ends up rewriting an analyst's case record

  2. Bundled Exabeam MCP bridge [PRAX-2026-09-07-001] The bridge returns that catalog verbatim — the one platform-sourced channel neither guardrail screens.
  3. soc-investigate skill (the loop) [PRAX-2026-09-07-001] The metadata lands in the model's context as tool documentation, countered only by a prose instruction in the skill telling it not to comply.
  4. PreToolUse gate hook [PRAX-2026-09-07-002] The influenced loop proposes a case or alert update; the gate asks the human to approve the call, not the free-text replacement it carries.
  5. Bundled Exabeam MCP bridge An approved update reaches the bridge with the model's chosen field values.
  6. Outbound neutralizer [PRAX-2026-09-07-002] The neutralizer defangs the content of the free-text fields but never reads or preserves their prior value.
  7. Remote Exabeam New-Scale MCP [PRAX-2026-09-07-002] Consequence: the analyst's existing description, name or closing reason is replaced in the tenant record with no read-before-write anywhere in the path.
Text planted in an alert becomes a case note the agent trusts in a later investigation
  1. Remote Exabeam New-Scale MCP Untrusted origin: alert, event and case content is authored by whoever triggered the detection — attacker-influenceable, with no provenance labelling.
  2. Bundled Exabeam MCP bridge The bridge forwards the tenant result into the local call path.
  3. Inbound canonicalizer Screening removes unambiguous smuggling code points only; ordinary instruction-shaped prose passes through unchanged.
  4. soc-investigate skill (the loop) The loop reasons over the payload and quotes it into the documentation it is instructed to write for every investigation.
  5. PreToolUse gate hook Case-note creation sits in the prompt-free allow tier, so the persisting write is never put to a human.
  6. Bundled Exabeam MCP bridge The note reaches the write path as an ordinary escalation write.
  7. Outbound neutralizer Formulas, links and credentials are de-activated; instruction-shaped prose is not in scope.
  8. Remote Exabeam New-Scale MCP Consequence: the planted text is now durable tenant record content that a later session retrieves as its own evidence, outliving the session that wrote it.
A hand-wired Exabeam connection lets a steered dismissal land with no prompt at all
  1. Remote Exabeam New-Scale MCP Untrusted origin: attacker-influenceable alert and event content arrives as the work item's evidence.
  2. Bundled Exabeam MCP bridge The bridge forwards the tenant result into the local call path.
  3. Inbound canonicalizer Only invisible smuggling code points are stripped; the benign-looking narrative survives.
  4. soc-investigate skill (the loop) The loop reaches a false-positive verdict on planted evidence and moves to the dismiss action.
  5. Bundled Exabeam MCP bridge [PRAX-2026-09-07-004] On the documented advanced install the operator's server name is not what the case-sensitive matcher expects, so the gate never runs and the optional permission rules do not spell that prefix either.
  6. Outbound neutralizer The write-side guardrail defangs the field content but has no say over the disposition.
  7. Remote Exabeam New-Scale MCP [PRAX-2026-09-07-004] Consequence: the alert is dismissed in the tenant with no human prompt, and neither the installer nor preflight can see that the install was un-gated.
