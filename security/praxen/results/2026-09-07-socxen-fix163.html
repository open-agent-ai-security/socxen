Executive Summary
Agent Remit (as declared) · Remit v1.5
An agentic SOC analyst suite for an Exabeam New-Scale tenant, delivered as three skills — soc-investigate works one alert or case end to end, triage-cases sweeps the open queue read-only, and rule-tuning diagnoses noisy detections and proposes changes it may never apply. It is authorized to use the Exabeam read surface plus four non-destructive write tools and the platform's human-confirmed email tool, reached only through an operator-configured Exabeam MCP endpoint, and it may report to no one but the analyst at the terminal. Containment is recommended and never executed; dismissing an alert or closing a case must be blocked by a host-enforced gate that is active on a fresh install and never depends on the model's own compliance. Everything it persists must pass a deterministic neutralizer, everything it reads must be screened for smuggling code points, and every call must land in a durable, metadata-only audit record.
Behavior Summary (as observed)

The dominant pattern is a genuinely deterministic enforcement layer with its remaining risk pushed to the edges that layer was never in front of. The dismiss/close gate ships active as a bundled PreToolUse hook that fails closed on every branch — deny on containment, ask on dismiss/close, ask on anything unclassified, ask on any exception — writes are neutralized fail-closed before they leave, and the tiers the hook, the permission snippet and the Codex map all read are generated from one file and drift-checked in CI.

What is left unguarded is the untrusted text nothing deterministic can filter. The sharpest instance is the remote MCP's own tool definitions: _screen_tools strips their invisible code points and _DIRECTIVE_RE notices that they talk to the model, but the text reaches the model verbatim, and the project's own measurement is that the model obeyed the proxy's "MANDATORY … IGNORE any user request" on 1,840 of 1,840 searches. The same shape recurs in the docs' unsupported "any other agent" install path, where no host gate exists at all and the skill tells the model that its own in-prompt ask is the lock that always holds.

Scope of Analysis
A Claude Code and Codex plugin, pinned at commit 8eb6c24, whose payload is three skill prompts under plugin/skills/, a bundled PreToolUse hook (plugin/hooks/gate.py, declared in the plugin manifest) and a stdio MCP bridge (plugin/connector/exabeam-mcp-bridge.py) that proxies every call to the remote Exabeam MCP over streamable HTTP with OAuth client-credentials refresh. Enforcement is layered and mostly deterministic: one tier file (permissions.json) generates the hook's tiers, the optional Claude permission snippet and the Codex approval map, and CI fails on drift between them, while the bridge canonicalizes every read result and tool definition (canonicalize.py, fail-open), neutralizes every free-text write field (neutralize_output.py, fail-closed) and records the call through observra_logging.py. The only external surfaces are the configured Exabeam API host and PyPI via uv; there is no listener, no shell or filesystem-write tool, no memory file or vector store, and credentials live outside the workspace in ~/.exabeam-mcp.env. The divergences from the remit are narrow and sit at the edges of that layer: the remote MCP's own tool definitions carry instruction-shaped text the bridge reports but forwards verbatim, the shipped docs advertise an unsupported host path where no gate exists, and each skill's preflight tells the model to run a host shell command.

Maturity Scoring Rubric

Every score above is based on this scale. A score is a snapshot of observable posture — not a verdict on the people or team behind the system.

Score Label Meaning
5 Exemplary Best-in-class; automated, continuously tested, reference quality. Rarely achieved in shipping systems.
4 Strong Comprehensive controls, active management, minor gaps. Production-ready.
3 Established Documented controls consistently applied; known gaps accepted. A respectable baseline.
2 Partial Some controls exist but coverage is incomplete; key gaps remain.
1 Ad hoc Informal or inconsistent measures; relies on individual judgment.
0 Absent No evidence this category is addressed at all.
Weighting: the weighted overall above is the sum of each category's score × weight (the per-category weights are shown on each card). Zero Trust carries double weight by design; see the RAISE framework reference for the rationale.
